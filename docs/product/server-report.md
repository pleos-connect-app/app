| 7 | **`shareUrl`이 실제 공유 페이지 주소.** `{PUBLIC_BASE_URL}/r/{토큰}`, 토큰은 추측 불가 128비트(22자), DONE 때 한 번 발급 | QR로 찍으면 열림. 단 서버의 `PUBLIC_BASE_URL`이 휴대폰에서 접속되는 주소여야 함(기본값 localhost는 휴대폰에서 안 열림) |
| 8 | **`videoUrl`은 영상 생성 전까지 `null`.** (mock 때는 열리지 않는 주소였음) | 앱은 `videoUrl`을 쓰지 않으니 영향 없음 |

## 4. 참고

- 후보 데이터: TourAPI 관광지 12,546곳 중 대표 이미지 없음·쇼핑·숙박·도시공원·교육/교통시설·좌표 오류를 뺀 10,520곳. 파일은 `server/src/main/resources/candidates.json`(커밋됨, 키 없이 서버 실행 가능). 동네 동상·협동조합처럼 드라이브 목적지로 애매한 곳이 일부 섞여 있어 기준을 더 다듬을 예정입니다.
- TourAPI 이미지는 공공누리 1유형(출처표시)·3유형(출처표시+변경금지)이 섞여 있습니다. 앱 결과 화면에 이미지를 쓸 경우 "사진: 한국관광공사" 출처 표시가 필요하고, 3유형은 자르지 않는 편이 안전합니다(서버 공유 페이지는 이렇게 처리).
- 서버 저장소는 아직 메모리라 서버를 재시작하면 트립·공유 링크가 사라집니다. 이때 앱이 `finish`를 다시 보내도 서버에 트립이 없어 `TRIP_NOT_FOUND`라 앱은 오류 화면으로 갑니다(요청서 5장의 "서버가 finish도 404로 주면 오류 화면"). 저장소를 DB로 바꾸기 전까지는 알려진 제약입니다.

## 5. 앱 답변 반영 (2026-11-12)

계약 정리는 `server/CLAUDE.md` "API 계약"에 반영했습니다.

- **3-1 `excludePlaceIds`**: 안 합니다.
- **3-2 `thumbnailUrl`**: `/recap` 응답에 추가합니다(nullable, https, `DONE`일 때만). 16:9, 리캡 영상 첫 장면(표지) 이미지이고 공유 페이지 영상 썸네일과 같은 이미지를 씁니다. 영상 생성(2-2)과 함께 넣습니다. 그전까지 앱은 지금처럼 목적지 사진을 보여 주면 됩니다.
- **3-3 `origin`**: 앱은 보내지 않습니다. 영상에 출발지 이름이 필요하면 서버가 `points[0]` 좌표로 찾습니다(앱과 같은 VWorld 역지오코딩, 시·구·동 단위).
- **3-4 `endReason`**: 안 합니다. 여행은 항상 사용자가 "여행 종료"를 눌러 끝나고, 도착 여부는 `DESTINATION_ARRIVED` 이벤트로 판단합니다.
  - 서버 영향: 도착 후 주변을 돌아다닌 기록도 `points`에 들어가므로 `distanceKm`·`durationMin`에 포함됩니다. 정차 판정은 원래 목적지 300m 안을 빼므로 목적지 주변에서 머문 시간은 정차로 세지 않습니다. 도착 후 다른 곳(예: 근처 식당)에 들렀다면 정차 1번으로 셀 수 있습니다.

### 실제 달린 경로를 지도에 그린 썸네일에 대한 의견

만들 수 있습니다. 서버에 경로 좌표가 다 있으니 지도 타일(VWorld) 위에 경로선을 그려 16:9 이미지로 저장하면 됩니다. 다만 한 가지 걸리는 점이 있습니다.

- **공유 페이지에 그대로 쓰면 출발지가 드러납니다.** 공유 페이지는 "출발지·경로 좌표를 넣지 않는다"가 원칙인데, 경로 지도는 출발 지점(대개 집이나 회사)을 그대로 보여 줍니다.

그래서 제안은 이렇습니다.

1. **우선 표지(영상 첫 장면)로 시작**합니다. 목적지 사진 + 이름 + "○○동 → 목적지" + 요약 수치. 공유 페이지에도 그대로 써도 안전합니다.
2. 경로 지도는 영상 안의 한 장면으로 넣되, **출발 쪽 처음 1~2km는 잘라내고** 그립니다. 이 방식이 괜찮으면 나중에 앱 결과 화면용 썸네일을 경로 지도로 바꾸는 것도 가능합니다(필드는 그대로 `thumbnailUrl`).

경로 지도를 썸네일로 원하시면 알려 주세요. 위 1번으로 먼저 진행하겠습니다.

## 6. 리캡 영상·썸네일 반영 (2026-11-12)

### 앱에서 달라지는 점

| # | 변경 | 앱에서 할 일 |
|---|---|---|
| 1 | **`/recap` 응답에 `thumbnailUrl` 추가.** `{shareUrl}/thumbnail.jpg`, 16:9(1280×720) JPEG. `DONE`일 때만 채워지고 못 만들었으면 `null` | 결과 화면에 붙여 주세요. `null`이면 지금처럼 목적지 사진 |
| 2 | **`videoUrl`이 실제 영상.** `{shareUrl}/video.mp4`, 세로 9:16 10초 MP4 | 앱은 쓰지 않아도 됨(공유 페이지에서 재생·저장) |
| 3 | **상태가 실제 생성 작업을 따름.** finish 후 `PENDING`(대기) → `RUNNING`(생성 중) → `DONE`/`FAILED`. 예전 "조회 3번째에 DONE" mock은 없앰 | 앱 동작 그대로(2초 간격 조회). 보통 10초 안팎에 `DONE`(지도 타일을 받으면 조금 더) |
| 4 | 생성 중 오류면 `FAILED` | "다시 시도"로 finish를 다시 보내면 새로 생성(3-5 그대로) |

`thumbnailUrl`·`videoUrl`은 `shareUrl`과 같은 공개 주소를 씁니다. 로컬에서는 `http://`이고, 배포 때 `PUBLIC_BASE_URL`을 https로 두면 https가 됩니다(합의한 "https"는 배포 기준).

### 영상 구성 (10초)

1. **표지**(0~2초): 목적지 사진, 날짜, 목적지 이름, "출발 동네 →"
2. **경로**(2~8초): 내비처럼 움직이는 카메라. 위에서 전체 경로를 보여 준 뒤 출발 쪽으로 내려와 55도로 기울이고, 차 화살표를 따라가며 진행 방향으로 지도가 돈다. 경로선이 뒤로 그려지고 정차한 곳에 빨간 핀, 거리가 올라간다. 도착하면 다시 올라가 전체 경로
3. **요약**(8~10초): "○○에 도착했어요"(도착 안 했으면 "○○로 떠난 드라이브"), 거리·시간·정차

썸네일은 표지와 같은 내용을 가로로 배치했습니다(왼쪽 글자, 오른쪽 사진. 사진이 없으면 경로 지도).

### 개인정보·저작권 처리

- **출발지 1.5km 안의 경로와 정차는 그리지 않습니다.** 공유되는 영상이라 집·회사 위치가 드러나지 않게 했습니다. 출발지는 "용산구 동자동" 같은 동네 이름으로만 나옵니다(5장에서 말씀드린 방식).
- 공공누리 3유형 사진은 자르지 않고 원본 비율로 넣습니다. "사진: 한국관광공사", 지도를 쓰면 "지도: 브이월드(국토교통부)"를 표시합니다.

### 서버를 켤 때 필요한 것

- **ffmpeg**(`brew install ffmpeg`). 없으면 영상 없이 썸네일만 나옵니다.
- (선택) **VWorld 키** `VWORLD_API_KEY` — 앱의 `randomdrive.vworldKey`와 같은 키. 있으면 경로 화면에 위성 지도와 출발 동네 이름이 들어갑니다. 없으면 단색 배경입니다.
- 자세한 방법은 [server-run-guide-macos.md](server-run-guide-macos.md) 0장.

### 부탁드릴 것

1. 결과 화면에 `thumbnailUrl`을 붙인 뒤 에뮬레이터에서 한 번 봐 주세요(가로로 크게 들어갔을 때 글자 크기·잘림).
2. 휴대폰으로 QR을 열어 영상 재생·저장이 되는지 봐 주세요(iPhone Safari, Android Chrome).
3. 영상 구성·문구에 의견이 있으면 알려 주세요.

### 알려진 제약

- 서버를 재시작하면 트립과 링크가 사라집니다(저장소가 메모리). 영상 파일은 디스크에 남지만 열 수 없고, 공유 기간(30일)이 지나면 서버 시작 때 지웁니다.
- VWorld 키를 서버에 아직 넣어 보지 못해 **위성 지도 배경은 실제 키로 확인 전**입니다. 키 없이 단색 배경으로 확인했습니다.
