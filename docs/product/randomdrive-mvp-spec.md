# 랜덤드라이브 기능 명세서 MVP

## 1. 서비스 개요

랜덤드라이브는 현재 위치와 이동 반경만 선택하면 차량에서 랜덤 목적지를 추천하고, 실제 주행 경로와 정차 순간을 자동 기록해 세로형 리캡 영상을 만드는 차량용 여행 서비스다.

주요 사용자는 친구·연인과 즉흥 드라이브를 즐기며 SNS로 경험을 공유하는 20~30대다. MVP는 취향·동행자·STT·LLM 입력 없이 “반경 선택 → 랜덤 목적지 → 주행 기록 → 리캡 영상 공유” 흐름에 집중한다.

## 2. 사용자 흐름

1. 사용자가 차량 정차 상태에서 앱을 실행한다.
2. 현재 위치를 기준으로 최대 탐색 반경을 선택한다. 기본 선택지는 50km, 100km, 150km이다.
3. 앱은 반경 내의 검증된 관광지·카페·전망대 등 후보를 불러오고, 접근 불가 장소와 현실적으로 방문하기 어려운 후보를 제외한다.
4. 랜덤 추첨 애니메이션으로 목적지 하나를 공개한다.
5. 사용자가 출발을 누르면 목적지를 Pleos 내비게이션에 전달한다.
6. 앱은 주행 중에는 조작을 요구하지 않고, 위치·시간·내비게이션 이벤트를 기록한다.
7. 목적지 도착 또는 여행 종료 후 서버가 주행 데이터를 받아 리캡 영상을 생성한다.
8. 사용자는 차량 화면의 QR 코드 또는 공유 링크를 통해 스마트폰에서 영상을 저장·공유한다.

## 3. 기능 명세

### F-01 반경 기반 랜덤 목적지 추천

- 입력: 현재 위치, 최대 탐색 반경
- 출력: 랜덤으로 선택된 목적지 1개
- 반경은 직선거리 기준으로 후보를 조회한다.
- 실제 도로 기준 이동 거리와 예상 소요 시간은 경로 API로 별도 계산한다.
- 후보는 관광지 후보 DB와 장소 정보 API를 기반으로 관리한다.
- 폐업, 출입 제한, 과도한 거리, 경로 탐색 실패 장소는 후보에서 제외한다.
- MVP에서는 재추첨을 제공할 수 있으나, 개인 취향 기반 추천은 제외한다.

### F-02 Pleos 내비게이션 목적지 전달

- 랜덤 목적지 확정 후 Pleos NaviHelper로 목적지 설정을 요청한다.
- SDK 연결이 완료된 상태에서만 요청한다.
- 연결 실패·경로 탐색 실패·너무 가까운 목적지·거리 초과 등 오류를 사용자에게 안내한다.
- 목적지 전달이 성공하면 차량 기본 내비게이션을 주 화면으로 우선한다.

### F-03 경유지 및 도착 이벤트 기록

- NaviHelper 이벤트 리스너를 등록한다.
- 기록 대상 이벤트:
  - 목적지 변경
  - 목적지 도착
  - 경유지 변경
  - 경유지 도착
- 내비게이션 앱의 구현 상태에 따라 실제 콜백 전달 여부가 달라질 수 있으므로 Pleos Emulator에서 우선 검증한다.
- 내비게이션에서 추가된 경유지는 “계획 경유지”로 저장한다.
- 경유지를 통과만 한 경우와 실제 체류한 경우는 구분해 표시한다.

### F-04 위치 및 주행 기록

- 기록 데이터: 시간, 위도·경도, 주행 거리, 이동 시간, 경유지·도착 이벤트
- 위치 기록은 Fused Location SDK 사용 가능 여부를 우선 검증한다.
- Fused Location SDK의 실제 배포 여부, 권한, 백그라운드 수집 가능 범위는 미확정 항목이다.
- 백그라운드 지속 기록, 앱 재실행 후 복구, 네트워크 단절 후 재전송, 위치 권한 거부를 각각 테스트한다.
- 위치 정보는 최소 수집 원칙에 따라 여행 기록 생성 목적에 한해 사용한다.

### F-05 예상 밖 정차 감지

- 계획 경유지와 무관한 체류 지점을 “예상 밖 정차 후보”로 수집한다.
- 단일 GPS 좌표만으로 정차를 확정하지 않는다.
- 판별 조건:
  - 일정 기준 이상의 체류 시간
  - 좁은 위치 반경 내 반복 위치
  - 정차 전후 주행 구간 존재
  - 계획 경유지 이벤트 여부
- 신호 대기, 교통 정체, 주차 대기 등을 정차 방문으로 잘못 기록하지 않도록 주행 로그 기반으로 보정한다.
- 초기 버전에서는 자동 감지 결과를 영상 생성 전 사용자가 제외할 수 있는 구조를 검토한다.

### F-06 주행 중 UI 및 멀티뷰

- 차량이 움직이는 동안 앱은 사용자의 조작을 요구하지 않는다.
- 주행 중에는 기본 내비게이션을 우선 표시한다.
- 앱은 필요 시 기록 상태, 경로 기록 여부, 영상 생성 상태만 간단히 표시한다.
- 멀티뷰 지원 여부와 표시 가능한 UI 범위는 Pleos 환경에서 검증한다.
- 주행 중 상세 지도 탐색, 재추첨, 영상 편집 등 주의를 분산시키는 기능은 제공하지 않는다.

### F-07 서버 리캡 영상 생성

- 여행 종료 후 앱이 서버로 주행 데이터를 업로드한다.
- 서버는 실제 이동 경로, 목적지, 경유지, 정차 후보, 주행 거리, 이동 시간을 기반으로 영상을 생성한다.
- 기본 출력:
  - 세로형 9:16
  - 약 8~12초
  - 지도 기반 2D 경로 애니메이션
  - 장소명·거리·시간·정차 순간 요약
  - MP4 형식
- 영상 생성은 비동기 작업으로 처리한다.
- 앱은 생성 대기, 생성 중, 완료, 실패 상태를 조회할 수 있어야 한다.
- 영상 기능은 Pleos SDK 기능이 아니라 별도 백엔드 구현 범위다.

### F-08 QR 및 공유 링크

- 영상 생성이 완료되면 고유 공유 링크를 발급한다.
- 차량 화면에는 스마트폰으로 확인할 수 있는 QR 코드를 제공한다.
- 링크에서 영상 재생·저장·공유가 가능해야 한다.
- 링크에는 사용자 개인정보, 차량 식별 정보, 원본 위치 로그가 노출되지 않도록 한다.
- 링크 만료 정책과 영상 보관 기간은 서버 정책으로 별도 정의한다.

## 4. 기술 구성

| 영역 | 주요 역할 |
|---|---|
| 차량 앱 | 반경 선택, 랜덤 추첨, 목적지 전달, 내비 이벤트 수집, 위치 기록, QR 표시 |
| Pleos NaviHelper | 목적지·경유지 설정, 경로 요청, 목적지·경유지 이벤트 수신 |
| 위치 모듈 | 위치·시간 로그 수집, 정차 후보 분석용 데이터 제공 |
| 백엔드 | 후보 장소 관리, 주행 데이터 수신, 영상 생성 작업 관리, 공유 링크 발급 |
| 영상 처리 | 지도 경로 렌더링, 텍스트 오버레이, FFmpeg 기반 MP4 인코딩 |
| 데이터 저장소 | 장소 후보, 여행 세션, 위치 로그, 영상 결과, 공유 토큰 저장 |

## 5. 확정 기능과 검증 과제

| 구분 | 항목 |
|---|---|
| 확정 구현 범위 | 반경 선택, 랜덤 목적지 추천, 서버 영상 생성, QR 공유 링크 |
| 공식 SDK 근거 있음 | NaviHelper 목적지·경유지 설정 및 관련 이벤트 리스너 |
| 선행 검증 필요 | Fused Location SDK 실제 사용 가능 여부, 권한, 백그라운드 GPS |
| 선행 검증 필요 | 멀티뷰 지원 범위, 주행 중 UI 제약, Navigation 앱별 이벤트 전달 차이 |
| 알고리즘 검증 필요 | 신호·정체와 실제 방문 정차를 구별하는 기준 |
| 제외 범위 | STT, 외부 LLM, 개인 취향 추천, 동행자 입력, 직접 영상 편집 |

## 6. 개발 우선순위

1. Pleos Emulator에서 NaviHelper 연결, 목적지 전달, 경유지·도착 이벤트 수신 검증
2. 반경 기반 후보 조회와 랜덤 목적지 추천 구현
3. 위치 기록 가능 범위와 권한·백그라운드 정책 검증
4. 정차 후보 판별 알고리즘을 샘플 GPS 로그로 검증
5. 서버의 샘플 GPS 기반 리캡 영상 생성 구현
6. QR 공유 링크와 영상 조회 화면 구현
7. 실제 주행 데이터로 차량 앱-서버-영상 생성 통합 시험

## 7. 완료 기준

- 사용자가 반경 하나만 선택해 랜덤 목적지를 받을 수 있다.
- 목적지를 차량 내비게이션에 전달할 수 있다.
- 목적지·경유지 이벤트 수신 여부를 Emulator에서 확인할 수 있다.
- 위치 기록이 실패하거나 권한이 없을 때 안전하게 중단·안내한다.
- 샘플 주행 데이터로 세로형 리캡 MP4가 생성된다.
- QR 코드로 스마트폰에서 결과 영상을 열 수 있다.
- 주행 중 화면 조작을 요구하지 않는다.
